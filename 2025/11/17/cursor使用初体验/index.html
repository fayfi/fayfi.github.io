cursor 使用初体验

发表于2025-11-17|更新于2025-11-17|AI
|总字数:2k|阅读时长:6分钟|浏览量:

引言

写一个可以在本地部署运行的app的demo要多久？
用cursor，只需要一周。
一周，可以完成这个app的初版开发，功能交互正常，无明显bug。
是的，这就是cursor，面向氛围编程。

我在上手一周以后，总结了用cursor开发app的一套流程，如下：

流程

第一阶段：产品定义

  • 输入： 产品创意

  • 输出： 清晰的产品定位文档

  • 任务： 明确产品为谁服务、解决什么问题、核心价值是什么。

第二阶段：UI风格定义

  • 输入： 产品定位文档

  • 输出： UI风格、页面线框图、参考图库

  • 任务： 确立视觉风格，为AI提供精确的模仿依据。

第三阶段：AI开发与构建

  • 输入： 产品定位 + UI风格

  • 输出： 可运行的应用原型

  • 任务： 构建Prompt，见下文通用prompt，AI生成代码，并运行原型。

第四阶段：测试与迭代

  • 输入： 应用原型

  • 输出： 经过验证和调整的可用的产品

  • 任务：

    • UI调整： 修正偏差，返回调整UI。

    • 功能验证： 测试增删改查等核心功能，返回修改Prompt。

    • 数据与Bug测试： 确保数据同步与系统稳定。

第五阶段：规范化审查

  • 输入： 测试通过的产品

  • 输出： 符合规范的可交付产品

  • 任务： 进行一致性、无障碍、安全性等最终检查。

项目指令

使用 [首选技术栈/语言，例如：Flutter, React, Python/Django] 设计、编码并实现以下需求。

全局约束：

  1. UI 语言： 全局UI和所有文案必须为 [UI语言，例如：英文/中文]。

  2. Mock 数据： 所有列表类页面请使用 [5-10] 条真实感的Mock数据填充。

  3. 核心技术约束： [例如：100% 离线优先 / 必须使用 [XYZ] 作为API后端]

通用prompt

以下为我总结的通用prompt，只需要发给ai自己的产品定位，让ai根据这个模板生成就好

1. 产品概述 (Product Overview)

  • 产品名称 (Product Name): [你的产品名称]

  • 产品愿景 (Vision): [用一句话描述产品的最终目标]

  • 目标用户 (Target User): [描述你的核心用户画像]

  • 核心价值 (Core Value):

    • [价值点 1]

    • [价值点 2]

    • [价值点 3]

  • **产品命名与元数据约束 (Naming & Metadata Constraints)**

    • **安全过审:** [描述必须避免的词汇，例如：避免 Love / Date / Match / Meet 等明确的Dating词]

    • **中性兼容:** [描述风格，例如：兼容生活社区和轻社交定位]

    • **字符限制:** [例如：标题和副标题限制在 30 字符内]

2. 全局技术与UI规范 (Global Tech & UI Specs)

2.1 技术栈要求 (Technical Requirements)

  • 开发语言/框架 (Language/Framework): [例如：Flutter, React Native]

  • 数据策略 (Data Strategy): [例如：全离线 / 远程 API 优先 / 首次启动拷贝种子数据]

2.2 **性能与平台约束 (Performance & Platform Constraints)**

  • **平台 (Platform):** [例如：仅支持手机竖屏 / 不支持 iPad / 必须兼容 iPhone SE]

  • **包大小 (App Size):** [例如：App 总包大小必须控制在 100M 以内]

  • **媒体优化 (Media Opt.):** [例如：所有用户上传的图片必须压缩处理 / 视频内容必须从后端流式获取，不能打包在App内]

2.3 UI/UX 规范 (UI/UX Style Guide)

  • 整体风格 (Aesthetic): [例如：简约现代, B2B专业风格]

  • 色彩系统 (Color Palette):

    • 主背景 (Main Background): [#XXXXXX]

    • 主色调 (Primary Color): [#XXXXXX]

    • 字体颜色 (Text Color): [#XXXXXX]

  • 按钮规范 (Buttons):

    • 主按钮 (CTA): [描述样式]

    • 次级按钮 (Secondary): [描述样式]

  • **截图规范 (Screenshot Style):**

    • **内容:** [描述截图应展示的内容，例如：体现核心功能，可增加气质在线的人物素材]

    • **安全:** [描述截图的底线，例如：避免过分性感、露肤、挑逗动作]

3. 应用架构与流程 (App Architecture & Flows)

3.1 应用架构 (App Architecture)

  • [描述App的顶层结构，例如：底部5-Tab导航 / 侧边栏抽屉菜单]

3.2 核心用户流程 (Core User Flows)

A. 流程 1: [注册与登录 (Auth Flow)]

  1. 注册方式: [例如：Email 注册 / 手机注册 / 社交登录]

  2. **可跳过项:** [例如：非必要信息（如昵称、头像）允许用户在注册时跳过]

  3. 登录页: [描述页面元素，例如：输入框 (邮箱, 密码)]

  4. **审核账号 (Review Account):**

    • **必须内置一个供审核使用的默认账号。**

    • [账号：review@example.com / 密码：password123]

  5. **合规链接:** 注册和登录页面必须清晰展示 [隐私策略], [服务条款] 和 [EULA] 的可点击链接。

B. 流程 2: [首次引导 (Onboarding Flow)]

  1. Page 1 [步骤1名称]: [描述功能，例如：上传头像、设置昵称]

  2. Page 2 [步骤2名称]: [描述功能，例如：选择兴趣标签]

  3. **年龄限制 (Age Gate):**

    • **必须包含年龄验证。**

    • [例如：使用生日选择器，必须确保用户年满 18+，否则弹窗提示无法注册]

4. 功能模块详细设计 (Feature Modules)

4.1 模块 1: [模块名称，例如：首页 (Home)]

  • 功能定位: [一句话描述]

  • 子功能: [描述具体功能点]

  • 交互细节: [描述关键交互]

(根据需要添加更多功能模块…)

5. 系统功能与数据 (System Features & Data)

5.1 **安全与审核 (Security & Moderation)**

  • 流程: [举报/拉黑 (Report/Block Flow)]

  • **触发点 (Entry Points):**

    • [必须在清晰、易于访问的位置提供举报/拉黑入口]

    • [例如：用户资料页 '...' 菜单 / 帖子 '...' 菜单 / 聊天会话 '...' 菜单 / 评论区]

  • **举报原因 (Reason Selection):**

    • [点击举报后，必须提供一个列表供用户选择具体原因（如：垃圾信息、骚扰、不当内容等）]

  • 执行逻辑 (Logic):

    • [描述拉黑后的行为，例如：拉黑成功后，该用户的所有内容和会话从当前用户视图中移除]

5.2 账号管理 (Account Management)

  • **登录状态 (Login State):**

    • [登录后，必须在本地持久化记录登录状态。用户下次打开App时，应直接进入应用内部（已登录状态），无需重新登录。]

  • 退出登录 (Log Out Flow):

    • [用户退出登录后，本地数据应保留。用户可使用同一账号重新登录，数据必须保持一致。]

  • 删除账号 (Delete Account Flow):

    • 路径: [例如：设置 -> 账号管理 -> 删除账号]

    • 流程: [例如：警告提示 -> 密码确认 -> 彻底清理本地数据 -> 返回登录页]

    • 验证: [删除后，该账号必须确认不可再登录]

5.3 **法律与合规 (Legal & Compliance)**

  • **应用内入口:** [必须在 '设置' 或 '关于' 页面提供可点击的入口，用于查看以下文档：]

    • [隐私策略 (Privacy Policy)]

    • [服务条款 (Terms of Service)]

    • [最终用户许可协议 (EULA)]

    • [（如果适用）订阅条款 (Subscription Terms)]

  • **文档格式:** [例如：可跳转至外部 Support URL (HTML 页面)]

  • **App Privacy (Apple):** [明确说明需要收集的用户数据（如：Email、昵称、用户发布内容）及其使用目的，用于填写 App Store Privacy 部分]

6. Mock 数据要求 (Mock Data Requirements)

  • **审核账号数据 (Review Account Data):**

    • **核心要求:** [必须为第 3.2.A 节中指定的 '审核账号' 提供一套完整、丰富、高质量的Mock数据。]

    • **数据清单:**

      • [例如：30+ 条完整的帖子]

      • [例如：50+ 件商品]

      • [例如：5+ 个包含真实讨论的聊天线程]

  • **数据真实性 (Data Freshness & Realism):**

    • **动态时间:** [涉及时间的内容（如帖子发布时间）应动态更新，显示为“最近一周”或“最近一个月”内，避免看起来像陈旧数据。]

    • **多样化:** [Mock数据应覆盖多种场景和风格，图片素材应避免重复，以免产生关联。]

Transformer 架构
一、Transformer 是什么？Transformer 是一种用于处理序列数据（如文本、语音）的深度学习模型。它最初是为机器翻译设计的，但现在已经成为自然语言处理（NLP）领域的主流模型结构，取代了之前的 RNN 和 CNN。 二、Transformer 的核心特点1. 自注意力机制 是什么：让模型在处理某个词时，能够权衡句中所有词的重要性，从而更好地理解当前词。 生活例子：翻译句子 I arrived at the bank after crossing the river. 翻译 bank 时，模型会给予 river 极高的注意力权重，从而正确翻译为“河岸”而非“银行”。 2. 位置编码 为什么需要：自注意力机制本身不考虑词的顺序。位置编码为每个词注入位置信息，告诉模型词语的先后顺序。 好比：在给每个词分配座位时，不仅告诉它是什么词（嵌入向量），还告诉它坐在第几排第几列（位置编码）。 3. 多头注意力 是什么：将注意力机制复制多份，让每一份（每个头）关注句子不同方面的信息。 好处：有的头可能关注语法结构，有的头可能关注指代关系，综合起来让模型的表征能力...
